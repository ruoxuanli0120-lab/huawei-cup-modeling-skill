# FALSIFY：三个认知 Pass

路线确认前从三个不同角度认真尝试推翻主线。不是重复做三遍实验，也不要求人为制造三份文件；三个视角可以引用同一份真实 pilot/推导，只要各自回答的问题和 finding/change 不同。

`team_control/route-Qn.json` 的 `iterations` 至少三项，`lens` 分别为 `architect / skeptic / reviewer`，每项包含：`question / lens / evidence / finding / change / risk`。`audit_core.route_report()` 检查三个视角齐全、证据真实存在、finding/change 不重复；不要求证据文件互不相同。

## PASS 1 · ARCHITECT

把主线路线落成可检验的模型或证明框架，并优先寻找更好的表示。

- 计算题：先做朴素 baseline/小规模原型，留下真实结果。
- 理论题：先写证明骨架、关键引理、边界条件或构造原型，不为了模板制造数值实验。
- 每个复杂模块必须对应一个已发现的基线失效或结构性困难；没有必要性就不加。

## PASS 2 · SKEPTIC

主动设计能推翻主线的低成本 killer test：

- 优化：紧约束、可行性、目标次序、下界/gap。
- 预测/统计：泄漏、划分、少数类、泛化。
- 机理/动力系统：量纲、守恒、边界、可辨识性、离散误差。
- 仿真：重复、收敛、尾部、有效样本量。
- 评价/排序：排名反转、权重/指标扰动。
- 理论/构造：最小反例、边界规模、必要/充分条件。

若关键假设被证伪，换路线或限定结论，不因已投入时间而保留。

## PASS 3 · REVIEWER

以评委视角回答六问：

1. 模型为什么适合本题？
2. 是否遗漏重要关系或约束？
3. 是否有更简单自然的模型？
4. 当前方法为什么适合这个数学模型/证明任务？
5. 若存在实质主要替代，为什么当前方案更合适？若没有，是否说明了不分叉的理由？
6. 当前证据是否足以支持最终结论？

任一核心问答不上，回到对应阶段修复。

## 纪律

- FULL 以 4–6 条结构不同路线为探索目标，FAST 以 2 条为目标，但路线数量不是硬质量指标；若额外路线只是同模型换算法，停止凑数。
- `ACCEPT_ROUTE` 前三 Pass 必须有效；批准绑定当前主路线和证据指纹，之后修改路线或证据会使批准失效。
- 三 Pass 不要求三次完整实现；可复用同一真实运行/推导作为证据，但三个视角必须真的回答不同问题，不能换措辞凑次数。
