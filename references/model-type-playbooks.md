# 题型自适应 Playbook

本文件是方法选择卡，不是算法百科。一个小问可以勾选多个类型；先写“主类型 + 辅助类型 + 选择证据”，再加载对应检查项。若题面同时要求解释机制、预测或决策，按接口拆成 Hybrid，而不是强行套一个模型。

识别类型后，按需读取 [excellent-paper-patterns.md](excellent-paper-patterns.md) 的同类经验；该文件只提供可迁移的选择、验证和失败模式，不提供历年题解。

## 共同骨架

```text
整题理解 → 小问数学本质与类型标签 → 题型基线
→ 候选模型与取舍 → 真实计算/算法或证明
→ 题型 Gate 验证 → 稳健性/边界 → 结果解释 → 论文
```

所有类型都保留：变量与单位、假设分层、必要的数据/代码或证明版本、真实运行或证明证据、失败记录、引用台账、结果—正文对账。优化题审查可行性与最优性证据；理论题根据命题审查证明链，不是所有构造题都需要下界。其它类型不自动要求全局最优证明。此处 Gate 是科学审查问题，不是脚本自动认证：记录适用项、证据及未解决项，不用“已按 playbook 检查”代替实质验证。

## 跨类型验证清单（验证模型与方法，不是验证程序能跑）

各类型 Gate 之外，用下列九类风险作通用检查池；**只回答与当前题型和结论有关的项，不适用的项不强求**。程序运行成功 ≠ 模型正确，指标更高 ≠ 模型更合适：

1. 假设是否合理——每条关键假设有依据，且不是为了让模型能跑而设；
2. 关键参数是否稳定——小扰动下结论不翻转；
3. 扰动是否稳健——输入/噪声/初始化扰动下解优雅退化而非崩塌；
4. 有无泄漏——时间/信息/标签泄漏，验证划分与可见时刻一致；
5. 能否泛化——留出集/新时段/新分布上仍成立，不以拟合代替泛化；
6. 优化解是否可行——满足全部约束，可还原、可修复、可解释；
7. 启发式是否与**精确解/理论下界/可靠基线**比较——给出质量证据，而非单次运行自夸；
8. 边界与极端条件是否合理——空/满/退化/极端参数下行为可解释；
9. 结论是否真的**回答题目**——对应所要求的产物、单位与口径。

## 类型卡

| 类型标签 | 先建的基线 | 核心 Gate（必须回答） | 高价值反思/稳健性 |
|---|---|---|---|
| 优化/运筹/调度/资源配置/组合优化 | 可行贪心、规则法或小规模精确解 | 可行性、约束覆盖、目标次序、上下界/Gap、规模与时间 | 改约束/权重/规模；若不能证全局最优，明确是启发式或限制族最优 |
| 统计/回归/预测/时间序列 | 均值/季节性/线性或朴素预测 | 时间或样本划分、泄漏、误差区间、残差、外推范围、泛化 | 滚动验证、留出期、异常/缺失处理、预测区间和参数敏感性 |
| 统计推断/实验比较（不同于预测） | 描述分布、组间效应量、简单估计及区间 | 抽样单位、重复测量、缺失机制、混杂、识别假设、区间/检验前提、多重比较 | 重采样/置换或稳健估计；不以不显著证明相同，不以显著证明有实际价值；等效性需给合理界值 |
| 分类/聚类/数据挖掘/机器学习 | 分类用多数类/规则；聚类用匹配数据距离的简单分组 | 分类查标签、类别不平衡、验证划分、阈值；无标签聚类查距离、簇数和业务意义，不强求分类准确率 | 分类查泛化/校准/误差案例；聚类查重采样/种子/尺度变化下的稳定性，外部标签可用时再评价一致性 |
| 机理/微分方程/差分方程/动力系统 | 量纲一致的简化模型或文献基线 | 假设、量纲、初边值、参数辨识、守恒/稳定性、实际观测验证 | 步长/参数/边界扰动；校准集与验证集分离，说明适用范围 |
| 随机过程/Monte Carlo/系统仿真 | 解析近似、少量重复或简单策略 | 随机变量和分布来源、种子、重复次数、收敛误差、置信区间 | 增加重复次数、换种子/分布、方差缩减；报告不确定性而非单次最优 |
| 综合评价/多指标决策/排序 | 等权、简单标准化或现行规则 | 指标方向/尺度、权重依据、相关指标重复计权、排序稳定性 | 权重/标准化/缺失值扰动；Spearman/Kendall或排名反转分析 |
| 图论/网络/路径/空间建模 | 路径用最短路；空间场用距离/邻域或插值基线 | 图问题查节点边/容量/可达性；连续空间查坐标、投影、分辨率、配准和空间依赖，不强建图 | 图问题做断边/改权重；空间问题做分区留出/尺度扰动/残差空间分布 |
| 数学构造/理论分析/证明 | 小规模枚举、显式构造或已知定理基线 | 定义域、必要/充分条件、边界反例、证明链、有限实验不能冒充定理 | 最小反例、边界规模、独立程序核验；只有证明覆盖的范围才称最优 |
| Hybrid 综合题 | 各子模型的简单基线及接口 | 子模型输入输出、单位/索引/时间接口、误差传播、联合目标和依赖 | 单独消融每个模块、端到端与分模块对照、接口扰动和总体稳健性 |
| 因果推断（条件性辅标签） | 先明确目标效应及识别设计；关联模型只能作对照 | 处理/结果、时间先后、混杂、可比性、识别假设和适用的安慰剂/敏感性；变量重要性不得冒充因果性 | 控制集/样本/时间窗扰动；识别失败就报告关联，时间先后本身不证明因果 |
| 时空数据（预测/机理/空间类型的辅标签） | 持续性、邻域或粗尺度基线 | 数据时空对齐、坐标/单位/分辨率、可用信息时刻、时空依赖及隔离验证 | 时间滚动与空间分区留出；极端事件/边界地区单独评估，不自动启用因果推断 |

## 优秀论文经验的调用方式

识别标签后，读取经验层的同类小节，记录“经验等级与来源定位—适用前提—当前题对应位置—第一项验证—失效后的修法”。先迁移拆题、选择和验证机制，再决定是否采用具体模型；外部方法/数据/代码仍进入真实来源台账。没有同类经验时按核心 Gate 做基线，不能虚构优秀论文背书。

## 三认知 Pass（对应 route-iteration.md 的三轮）

Pass 的完整定义与杀手实验纪律见 [route-iteration.md](route-iteration.md)；路线的生成与竞争见 [model-ideation.md](model-ideation.md)。这里给各 Pass 的题型攻击重点：

1. **PASS 1 · ARCHITECT**：完成题意映射（来自 Problem Insight Map）、题型基线、候选比较和第一版真实结果；发现更简单的表示时应评估替换主线（更好的表示 > 更高级的算法）。
2. **PASS 2 · SKEPTIC**：攻击该类型最关键的失效模式（如泄漏、约束遗漏、量纲错误、随机不收敛、权重反转或证明反例），用**低成本高区分度的杀手实验**留下证据；证伪优先，禁止沉没成本保留。
3. **PASS 3 · REVIEWER**：以评委视角**先答主六问**（模型为何适合本题 / 有无遗漏关系或约束 / 有无更简单更自然的模型 / 当前求解方法为何适合这个数学模型 / 主要替代方法为何不如 / 实验与验证是否足以支持结论），再用 11 细化问补充；任一核心问答不上即回退重新建模或重选方法。根据证据改模型或限定结论，做最终稳健性检查并明确仍未证明的部分。

三 Pass 都要有真实变化或理由保留方案；“反例+下界”只在理论/构造或确实存在离散最优性主张时作为核心问题。

## 新题型扩充卡

当现有标签不够：记录题型名称、输入输出、基线、主要风险、核心指标、三轮攻击方式和优秀论文可迁移机制；先作为 `Hybrid/待定` 执行，不把未经验证的新标签写成永久规则。
