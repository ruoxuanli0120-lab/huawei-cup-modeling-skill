# 建模构思与路线竞争：IDEATE → SELECT

本文件覆盖 9 阶段工作流的第 2–3 步。前置：已完成 [problem-intelligence.md](problem-intelligence.md) 的 Problem Insight Map（数学本质、结构、表示备选、核心洞察、小问依赖）。**没有 Insight Map 不允许进入本阶段。**

> 原则重申：抓更好的**表示**，不是更高级的**算法**。本阶段的目标是把 Insight Map 里的 Representation Alternatives 展开成若干**结构不同**的候选路线，再用低成本证据快速淘汰平庸路线，只让最有希望的 1 条主线（+至多 1 条挑战者）进入 FALSIFY/BUILD。

## 第 2 步 · Model Ideation Engine（构思广，实验窄）

### 以 4–6 条“结构不同”的路线为探索目标

- 数量目标 **4–6 条**，宁缺毋滥；若题目确实只有一种合理构造，写明**唯一性依据**，不硬凑。
- “结构不同”指**表示/抽象/机理不同**，不是换库、换超参、换随机种子。
  - **Random Forest / XGBoost / LightGBM / GBDT 属于同一条路线**（都是“表格特征 → 树集成回归/分类”的同一表示），只能算 1 条，不能拆成 3 条凑数。
  - 同理：换求解器、换优化器、换网络层数、换聚类距离度量，都不是新路线。
- 真正的结构差异来自 Insight Map 的不同表示，例如：原始变量优化 vs 对偶/松弛 vs 图/网络流 vs 概率生成模型 vs 机理微分方程 vs 统计经验模型 vs 显式构造/组合论证 vs 代理/降维表示。
- **构思阶段允许大胆**（广），但**进入实验的路线要少而准**（窄）：绝大多数路线应在纸面比较或小规模判别实验内被淘汰，不要求逐条完整实现。
- 每条路线用 `run_state.py route add --structure-tag <数学结构标签>` 注册；tag 是**数学结构**（如 continuous-relaxation / network-flow / mechanistic-ode），不是求解器品牌——“同一模型 + 遗传算法 / 模拟退火 / 粒子群”是**同一条路线**，gate 会拒绝 tag 雷同的凑数注册（见 [run-state.md](run-state.md)）。

### 每条路线只保留一张简洁决策卡

不要为了流程填写 13 项表格。每条实质路线只记录下面 6 件事，能直接支持选择即可：

1. **表示/模型**：它如何表示本题对象、关系、变量、约束和目标；
2. **题目契合与关键假设**：为什么贴题，成立依赖什么；
3. **信息可行性**：现有数据/信息是否足够，有无泄漏或不可得条件；
4. **区分证据**：什么最小 pilot、推导、反例或 exact case 能把它与主要替代区分开；
5. **成本与失效条件**：实现/算力风险，以及什么现象出现就应淘汰；
6. **与其它路线的关系**：结构等价就合并；互补才考虑 hybrid；明显被支配就淘汰。

## 第 3 步 · Candidate Route Tournament（路线竞争淘汰）

优先做**定性 + 证据**比较：结构契合、可验证性、信息可行性、成本/风险、预期收益。只有候选难以区分、且数字化评分确实帮助决策时，才临时使用评分表；权重必须解释，但分数本身不是证据，也不是机器门。

### 裁决：KEEP / PILOT / KILL

- **KEEP**：证据充分、明显占优 → 直接进入主线或挑战者。
- **PILOT**：有潜力但关键假设未验证 → 先做决策卡里的**低成本区分实验**再定去留；PILOT 不是“先全实现看看”。
- **KILL**：结构不契合、被支配、信息不可得或成本失控 → **带证据淘汰**。
  - **禁止沉没成本保留**：已经花了时间/写了代码，不构成继续的理由。淘汰只看前瞻证据。
  - KILL 要写清“被什么支配/为什么不契合”，以便论文说明选择依据。

### 输出：1 主线 + ≤1 挑战者

- 锦标赛**必须收敛到 1 条主线**（main），外加**至多 1 条挑战者**（challenger）。
- 挑战者只在“与主线结构不同、且区分实验显示可能更优”时保留；否则只留主线。
- 不允许把 4–6 条全部带进 BUILD——那等于没有做选择，回到“算法大全”陷阱。
- 主线 + 挑战者的选择依据（决策卡 + 区分证据/KILL 理由）要留档，供论文“模型选择”一节与 route gate 引用。
- 裁决落盘到 run-state：`route status --status main|challenger|killed --evidence ...`（killed 必须带证据，无证据的 kill 被拒绝；多主线/多挑战者被拒绝）。主线经 FALSIFY 三 Pass 后由用户 **ACCEPT_ROUTE** 审批，才允许进入 BUILD——算法高级程度不是加分项，题意贴合度、可验证性与结构利用才是。

## 求解方法由数学模型决定（SELECT → BUILD）

路线/主线确定的是**模型是什么**；本节确定**这个模型怎么求**。方法从模型的数学属性推出，不是先选方法再套模型。

先读模型属性，逐项回答：
- 连续还是离散？线性还是非线性？凸还是非凸？是否可微？
- 是否整数/组合优化？是否随机？是否多目标？
- 约束结构是什么（等式/不等式/逻辑/耦合/稀疏）？
- 搜索空间规模多大？
- 是否存在**解析法或精确算法**（LP/MIP 求解器、KKT、动态规划、最短路、闭式解等）？
- 小规模能否**精确求解**（用作对照/下界）？
- 比赛时间与算力预算是多少？

然后选择方法，并写出两句话：
> **为什么这个方法适合当前数学模型？**（它利用了模型的哪个属性？）
> **若存在实质主要替代，为什么它没有当前方法合适？**（只比较真正可行的主要替代；没有则说明为什么不需要人为制造替代。）

**禁止凭口号选方法**（下列单独出现即拒绝）：
- “GA 全局搜索能力强”“PSO 收敛快”“模拟退火实现简单”；
- “LSTM 能处理长期依赖”“XGBoost 精度高、开箱即用”；
- “别人都这么用”“看起来更高级”。
这些说的是算法的通用卖点，没有回答**它为何适合这个模型**。凸可微连续问题应优先考虑梯度类/精确求解器；能用动态规划就不该上进化算法；小规模可精确求解就不该不做对照直接上启发式。

### 从模型属性推方法：构造性映射（优先更简单/更精确）

选方法不是背算法，而是**读属性 → 顺阶梯下沉**。先走"简单/精确优先"阶梯，只有当上一级确实不适用才下沉，并**写下下沉理由**：

> **解析/闭式 → 精确算法 → 凸化/松弛/等价转化 → 有保证的近似 → 启发式/元启发式（F 项须与下界·精确解·基线比较）**

按模型属性的首选方法族（用于"由属性推方法"，不是新口号；非穷举）：

| 模型属性 | 首选方法族 | 何时才下沉到启发式 |
|---|---|---|
| 可解析求解/闭式 | 直接推导、闭式解 | 几乎不需要 |
| 线性规划 LP | 单纯形/内点（求解器） | 规模过大时考虑近似/列生成 |
| 凸 + 可微（无/有约束） | 梯度下降/牛顿/拟牛顿；约束用 KKT/投影梯度/凸优化求解器 | 非必需——凸多有全局保证 |
| 非凸但可微 | 多起点梯度、信赖域，配合凸松弛给下界 | 多起点仍困局部且确需全局时 |
| 整数/组合，小规模可精确 | MIP 求解器、分支定界、枚举 | 规模超出精确可解时 |
| 最优子结构 + 无后效性 | 动态规划 | 状态维数爆炸时 |
| 图/网络结构 | 最短路、最大流、匹配、生成树、网络流 | 附加约束破坏图结构时 |
| 大规模组合爆炸、无精确保证需求 | 局部搜索/模拟退火/GA/禁忌（**必须给下界或基线比较**） | —— |
| 随机/不确定 | Monte Carlo/随机规划/仿真（重复·收敛·区间） | —— |
| 多目标 | Pareto 前沿、加权、字典序（先定优先级依据） | —— |
| 缺失数据下的估计/预测 | 与题型基线对照的统计/ML（见 [model-type-playbooks.md](model-type-playbooks.md)） | —— |

用法：读属性 → 从阶梯**顶端往下找第一个适用**的方法族 → 用上面"必答两句"说明为何它适合、主要替代为何不如 → 过 Method Suitability Test（A–F）。**下沉到启发式必须说明上层为何不适用**，否则按口号选法处理。

## Method Suitability Test（进入正式求解前必过）

使用唯一模板 [method-suitability.md](../templates/method-suitability.md) 回答 A–F。六项都要回应，但**按题型解释**：计算题写模型结构、候选方法、合法性和验证；理论题写证明障碍、替代证明、引理/构造与命题结构的对应、条件/反例和 proof review。不要为了模板强迫理论题讨论求解器、小规模数值实验或 objective。

判定只看一件事：**当前方法是否比主要替代更贴合当前模型/命题，并且有可验证的正确性路径。** 任一项无法合理回答，就回到模型或方法选择，而不是用算法口号补空。

## 方法内部设计必须真正对应本题（建模要求，非论文堆砌）

这是**建模过程**要求：要想得细；论文只写**真正影响模型合理性与结果可信度的关键设计**，不写成算法教材。

以遗传算法为例，建模阶段必须想清楚并自然对应：
- **chromosome**：表示什么决策方案？**gene**：对应什么决策变量？
- **fitness**：如何对应原目标函数（含单位/罚项/方向）？
- **encoding**：为什么适合当前决策结构（排列/二进制/实数/分组…）？
- **crossover**：为什么不会破坏当前编码或本题重要结构（顺序/容量/分组/连通性）？
- **mutation**：对应什么局部改变，步长如何定？
- **constraints**：怎样处理（罚函数/解码器/修复/拒绝）？**repair**：怎样恢复可行解？
- **initialization**：是否利用本题结构（贪心/规则/热启动），而非纯随机？
- **termination**：怎样根据收敛与算力预算确定？

> **若这些无法自然对应本题 → 重新考虑遗传算法（或该方法）是否真的适合**（回到 Method Suitability Test）。其它方法同理：优化器的梯度/次梯度、MCMC 的提议分布、神经网络的输入表示与损失、聚类的距离与簇数，都要映射到本题的变量、目标与约束。

## Copy-Paste Test：检查“方法是否真的贴题”，不是写作形式主义

Copy-Paste Test 的唯一目的：**判断求解方法是不是实际上没有针对当前数学模型做设计**（即它是不是一段可贴到任何题目上的模板）。

- **不要**用它逐句挑论文措辞。“遗传算法通过选择、交叉、变异搜索最优解”这种话本身不是大问题。
- 真正的问题是：若整个方案**除了这句通用描述**之外，没有解释怎么编码本题变量、怎么处理本题约束、fitness 为什么等于本题目标、crossover/mutation 是否适合本题结构，那么方法很可能只是**套用**。
- 判定法：把方法描述**原样换到另一道题**上是否照样成立？若成立，说明它没有针对本题设计。重点检查**建模设计是否可替换**，而不是挑写作。

## 创新必须服务于模型合适性

创新优先从这些地方找（按优先级）：
- 更好的**问题表示**；更合理的**状态变量**；更符合机制的**模型项**；
- 更好的**问题分解**；更合理的**模型耦合**；针对**已观测 baseline failure** 的定向改进。

**算法换新版本只是次级创新**（新求解器/新优化器/新网络层）。每个创新点都必须回答：
> **它解决了原模型的什么具体问题？**
没有明确答案就**不要增加**。创新不是为了显得高级，而是为了让模型更贴题、方法更贴模型。

## 复杂度正当性（Complexity Justification）——贯穿 SELECT/BUILD

**每一处复杂度增加，都必须修复一个具体的、已观测到的基线失效模式。**

- 合法理由（必须给证据）：基线在某类样本/工况/约束上**实测失败**，且该复杂度**针对性**修复它，并有区分实验证明修复有效。
- **非法理由（单独出现即拒绝）**：
  - “深度学习是 SOTA / 更强”；
  - “群智能/进化算法搜索能力强”；
  - “集成更稳”；
  - “参数更多所以更准”；
  - “别人论文用了”“这样看起来更高级”。
- 判据（写进论文与 route gate）：
  > **利用题目结构的简单模型，优于与题目结构无关的复杂算法。**
- 实操：先建**最朴素基线**并跑通 → 观测其**具体失效** → 只针对该失效引入**最小**必要复杂度 → 用区分实验证明收益 > 成本。没有观测到失效，就不加复杂度。
- 复杂度审计在 FALSIFY（SKEPTIC pass）与 BUILD 复核；任何无法指向“修了哪个基线失效”的复杂模块，按 KILL 处理并回退到更简单表示。
