# Contributing to Huawei Cup Modeling Skill

Thank you for your interest in contributing to the Huawei Cup Modeling Skill.

Contributions of all kinds are welcome, including bug reports, documentation improvements, new modeling methods, scripts, templates, and workflow improvements.

## How to Contribute

### Report a Problem

If you find a bug, incorrect modeling recommendation, broken script, or unclear documentation, please open a GitHub Issue.

When reporting a problem, please include:

* A clear description of the problem
* Steps to reproduce it, if applicable
* Expected behavior
* Actual behavior
* Relevant files, screenshots, logs, or examples

## Suggest a Feature

Feature requests are welcome.

Examples include:

* New mathematical modeling methods
* Additional validation tools
* New competition workflows
* New templates
* Improved paper-review procedures
* Support for additional modeling competitions

Please open an Issue before making a large change so the proposal can be discussed first.

## Pull Requests

To contribute code or documentation:

1. Fork this repository.
2. Create a new branch.
3. Make your changes.
4. Test your changes where applicable.
5. Commit your changes with a clear commit message.
6. Open a Pull Request.

Please keep each Pull Request focused on one main improvement.

## Modeling Contributions

When adding or modifying a mathematical modeling method, please explain:

* What type of problem the method is suitable for
* Important assumptions
* Required data
* Limitations
* Validation methods
* Relevant references when appropriate

The goal is to keep modeling recommendations reproducible and technically defensible.

## Documentation Contributions

Documentation improvements are welcome, including:

* Fixing unclear explanations
* Improving examples
* Correcting formatting
* Adding usage instructions
* Improving English or Chinese documentation

## Code Contributions

For scripts and automation tools:

* Keep the code readable
* Avoid unnecessary dependencies
* Document important parameters
* Include basic error handling
* Provide an example when possible

## Questions

If you are unsure whether an idea fits the project, open an Issue and describe your proposal.

Thank you for helping improve the project.
