# Problem Insight Map（Step 0 题面审计 + 问题智能）

UNDERSTAND 阶段的填写产物。方法出处见 [references/problem-intelligence.md](../references/problem-intelligence.md)。
硬规则：**问题结构 → 数学抽象 → 数学模型 → 求解方法**（等价展开：结构 → 抽象 → 机理 → 路线 → 算法），禁止 algorithm-first。核心原则：抓更好的**表示**，不是更高级的**算法**；模型先从问题建立，方法再由模型属性决定。每一项都要落到**本题证据**，不写通用套话；不适用写“不适用 + 原因”。

## 1. 官方定义摘录（Task / Variables）

- 题目/小问：
- 所求结论/输出及评价指标（有目标函数时写清口径）：
- 数据、观测量、未知量/可控变量及维度、单位、取值域、可见时刻：
- **变量四分类**（各类分别列维度/单位/取值域/可见时刻；混淆状态与决策是建模错误的常见根源）：状态变量 / 决策变量（在决策什么）/ 观测变量 / 参数：
- 约束、边界、单位：
- 数据时间/空间/实体单位与可用信息边界：
- 运算/成本计数（相关时填写）：
- 官方来源文件与页码：
- 字面要求 / 工程修复后的要求 / 二者差异（分开记录）：

## 2. 数学本质与结构（Mathematical Essence / Structure / Difficulty）

- **Mathematical Essence**：剥掉行业背景后这是什么数学问题（一句话），以及为什么不是别的本质：
- **Structure**：变量间的关系结构（线性/非线性、凸/非凸、可微/不可微、连续/离散、稀疏/稠密、静态/时序、可分/耦合），以及有无 **时间/空间/网络/阶段（多阶段·DP）/随机/反馈/守恒量·不变量**、天然图/几何/概率结构（结构决定抽象，抽象决定模型，模型决定可用方法）：
- **Difficulty**：本题真正的难点（规模/不可辨识/约束冲突/信息缺失/多目标/病态/随机性/证明门槛），而非“算法难写”：
- **数学模型雏形**（从对象/关系/约束建立，非先有算法再套题意）：目标函数 + 约束 + 变量域（并写明每个决策变量在决策什么）：
- **领域理论深度**（仅当机理改变模型结构时填；否则写“轻量：背景包装，数学本质通用”）：关键机制/支配方程/变量与单位/初边值条件/守恒关系/核心假设/适用范围/主要量级（主导项·可忽略项）：

## 11. 审计结论与闸门

- 实际理解的任务与预期交付：
- Core Insight 是否已能一句话陈述（否则不得进入 IDEATE）：
- 表示备选 ≥ 2 个（否则回到第 5 节）：- 变量是否已按 状态/决策/观测/参数 分清，且已建立**数学模型雏形**（目标+约束+变量域），而非先有算法再套题意：
- 若领域理论改变模型结构，是否已写清 支配方程/单位/初边值/守恒/量级/可忽略机制；若不改变，是否保持轻量：
- 多问题目依赖图是否自洽、主线是否统一：
- 候选/基线及区分实验：
- 新增假设或工程修正（如有）与影响：
- 必须验证的风险：
- **Problem-to-Model Traceability**：已按 [traceability.json](traceability.json) 模板建立 `team_control/traceability-Qn.json` 并通过 `run_state.py trace check`（每个变量/约束/目标都能回答“对应题目中的什么”；orphan=建模风险；题面未入模型的条件已列理由）：是 / 否
- **route gate status：`OPEN / BLOCKED`**（BLOCKED 时列出阻塞项；依赖没理清不得进入 IDEATE）
